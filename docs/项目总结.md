## 一、项目是什么

《领地：种田与征战》(Steam appid 1455910, Unity 2022.3.62f3) 的 **BepInEx 6 / IL2CPP / HarmonyX** mod。

- 插件 GUID：`claude.facility`，命名空间 **`FacilityMod`**（不是 `Facility`，否则和游戏类型撞名）
- 定位：**实验性项目** —— 目标不是做一座建筑，而是把「自定义建筑 / 自定义物品 / 原生 UI」的路子全部趟通，
  为后续的**工业 mod** 铺路
- 部署链路：`dotnet build -c Release` → 自动复制到 **`C:\TerritoryModTest`**（官方本地测试通道）
  → 游戏启动时镜像到 `BepInEx\plugins\<槽位>`

## 三、三条已跑通的支柱（这是本项目最有价值的产出）

### 支柱 1：自定义建筑 = 五张 Def 表

```
stuff.json     建筑本体（stuff_id/prefab/stuff_img/stuff_img_on_map/type）
build.json     建造参数（class_name/cellw/cellh/window_prefab/menu_group/have_worker/材料）
tech.json      建造菜单归属（tech_id + txt_id 决定分类）
career.json    工人职业（npc_type/manpower_limit）
blueprint.json 配方（facility_id + _material_N/_nN + product_id + output_count + days）
```

**关键铁律（都踩过）**：
- 只放 stuff+build **不够** —— 缺 career 则不能派工、缺 tech 则不出现在建造菜单
- **`tech_tree.json` 补丁通道不支持**（写了也不加载）→ 免科技就把 `tech_id` 设 0
- `txt_id` 是**分类段号**，必须与 `menu_group` 配对：100=初始 200=住所 300=食品 3700=制造 1500=物流 600=路桥
- **骨架 prefab 的占地必须与 `cellw/cellh` 一致**（拿 3×1 的 `workbench` 当 3×2 用 → 模型只画 1×3）

### 支柱 2：自定义外观 = 复用 prefab + 运行时换图

**不要新建 prefab**（三条死路：`action="add"` 新名字放置崩、`action="replace"` 洋红探针实测无效、
自造 GameObject 拦 `PrefabManager` 游戏从不请求那个名字）。

正确做法（`CustomSprite.cs`）：
```
stuff.json : prefab = 游戏已有 prefab；stuff_img_on_map = 我们新增的名字
textures.xml: action="add"，4 个朝向 super_factory_0..3，anchor="0,0"
DLL        : 每帧状态校验（不依赖"做过没做过"的缓存）：
             ① sp_body.sprite_id  ← 批渲染只认这个
             ② 关掉自带渲染器 sr.enabled（不要关 GameObject）
             ③ 自建 SpriteRenderer 兜底
```
- **贴图规格**：游戏是 **32 像素/格**（`Tile.CELL_SIZE_IN_PIXEL=32` / `CELL_SIZE=1`），
  ppu 由游戏常量算出。3×2 建筑用约 96×64 的图
- **多个建筑别共用同一个 prefab**：`sprite_id` 指向共享图集，改一个会把另一个一起换图

### 支柱 3：原生 UI = 换 window_prefab + 自己填数据

**核心结论**：建筑的窗口外观由 `build.json` 的 **`window_prefab`** 决定，**与 `class_name` 可以不一致**。

- 换成 `window_blacksmith` → 白拿一套原生 UI（含原生下拉 `dp_blueprint`，标准 `TMP_Dropdown`）
- 数据自己填：`NativeDropdown` 用 TMP_Dropdown **标准 API**
  （`ClearOptions` / `AddOptions(List<OptionData>)` / `SetValueWithoutNotify` / `RefreshShownValue` / `onValueChanged`）
- 取控件用 `NativeUi.Find<T>(window, "字段名")` —— 按**窗口类的 `[SerializeField]` 字段名**反射

**归属判断必须 fail-safe**：判不出是不是我们的窗口 → **不动**。
（踩过：宽松放行导致把**原版制造台**窗口的材料/进度/取用范围全隐藏了）

**安全护栏**（`NativeWindowSafetyPatch`）：借来的窗口里，依赖工坊组件的方法在我们建筑上会空引用，
要跳过 —— `WindowWorkshop.ShowWindowTip / InitDpBlueprint / InitWorkshopOptionData / …` 共 7 个。

## 五、必须记住的坑（按严重程度）

1. **判不出归属时"放行"** → 会改坏原版 UI。**必须 fail-safe（不动）**
2. **按物体名全局搜控件** → 命中同名物体误伤原版窗口。只在**已确认是我们的窗口**子树内才按名找
3. **隐藏控件前检查它是不是要保留控件的祖先** —— `fomula_item_main` 就是原生下拉的父容器，隐藏它 = 下拉消失
4. **运行时新增/删除 GameObject 改样式** → 游戏进档后**静默退出**（连 ErrorLog 都不写）。只用改颜色/尺寸
5. **挂游戏业务方法做重活** → `AccessViolationException` 崩游戏。跨帧对象操作只在主线程 `Update` 里做
6. **`sizeDelta` 不等于宽度** —— 锚点会横向拉伸时它只是增量；宽度要用 `rect.width`
7. **IL2CPP 三坑**：lambda 不能隐式转 `UnityAction<T>`（要显式 new）；
   `AddOptions(List<string>)` 不生成（要自己构造 `List<OptionData>`）；控件处理顺序（早 return 会跳过后面）
8. **改完代码必须重启游戏** —— 否则跑的还是旧 DLL（「日志关不掉」的真因）
9. **动玩家存档前先备份**（踩过：测试把玩家 4 座建筑弄丢，靠旧档找回）
10. **日志**：`LogV` 走 cfg 详细模式；启动横幅带版本号，一眼确认加载的是哪一版

## 六、反编译语料库的用法（强烈推荐）

`C:\AI\游戏向量库\code_meta.json` —— 54895 条真函数实现（伪 C，含字段与调用关系）。
比 interop 字符串扫描强得多：

```bash
python _tools/probe_code_db.py --find WindowFurnace          # 找相关文件
python _tools/probe_code_db.py --show WindowFurnaceSetInfo   # 看实现
python _tools/probe_code_db.py --strings WindowWorkshop      # 看字符串常量
```

**已知局限**：字符串常量大多是 `StringLiteral_xxx`，所以**预制体名字符串拿不到** ——
需要预制体名时改用「游戏内 UnityExplorer（F7）看层级」这条路。
