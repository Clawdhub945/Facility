工业 mod（方案 B）：新增 3×3 自研高炉 —— 燃料/配方/产出由本 mod 实现

## 用户决定
「高炉要的是 3*3 的」→ 选方案 B（3×3 自研炉）。

## 为什么必须自研（对照实验结论）
`window_furnace` 的控件依赖 **prefab 上的 `FacilityFurnace` 组件**，
而原生熔炉骨架是 **2×2**。借 3×3 骨架配 `FacilityFurnace` 的实测结果是
「窗口能显示但控件不可交互」（配方下拉空、燃料按钮点不动）。
→ 要 3×3，就必须自己实现燃料 + 配方 + 产出。

## 新增：`SmelterConsumer.cs`（自研冶炼内核）
工作模型（刻意从简，便于扩展）：
* **入料**：玩家把材料（铁锭）与燃料（煤）放进建筑仓库
  （骨架自带存储界面）
* **每天结算一次**（挂在本 mod 换日流程）：检查料够不够 → 够就扣除并产出
* 材料与**燃料分开记账**（工业 mod 里"烧什么"要能单独配）
* 未开工时记录**原因**（`BlockReason(guid)`，供窗口提示/诊断）

规范化：`SmeltingRecipe { Inputs, FuelId, FuelPerBatch, OutputId, OutputCount }`
挂在 `BuildingSpec.Smelting` 上 —— 以后加"烧铁矿出铁锭"的炉子**只改规格，不动逻辑**。

⚠ 技术点：`Bag.stuff_dic` **不在 interop 程序集里**（编译不过），
所以 bag 读写统一走**反射**（字段名在反编译语料库确认），
并带兜底扫描（挑键为 int 的 IDictionary），拿不到就记日志而不抛异常。

## 新增建筑 105054「高炉」(3×3)
| 项 | 值 |
|---|---|
| 骨架 | `trading_desk`（3×3、无地形限制、自带仓库） |
| class_name | `FacilityTradingDesk`（**不用** FacilityFurnace，避免 2×2 限制） |
| window | `window_gatherers_hut`（有工人/存储界面；我们最熟） |
| 占地 | **3×3** |
| 规格 | `DailyProducer=false` / `Smelting={铁锭×2 + 煤×1 → 钢×1}` / 不改窗口文案 |

冶炼配方的**燃料是煤**(601001)、产物是钢(603010)。

## 为什么保留 2×2 版本
105053（原生熔炉机制，2×2）保留 —— 它功能原生完整（配方下拉/燃料设置/进度都可用），
可以作为对照与备用；3×3 版是主力。

## 待验证（需游戏内操作）
1. 建造菜单能否看到两座「高炉」（2×2 与 3×3）
2. 建成 3×3 后，把**铁锭与煤**放进它的仓库
3. 跨几个游戏日，看是否自动产出钢（日志会打「开工：消耗 …」或「未开工：缺少 …」）
4. 物品图标（钢/钢制工具/高炉）是否显示正常（上轮已修 textures.xml，本次重启生效）
