对照实验结论 + 熔炉配方克隆（新建筑继承原生熔炉全部配方）

## 对照实验结论（用户实测）
| | 105052 熔炉对照（furnace 骨架） | 105028 原生熔炉 |
|---|---|---|
| 工作类型下拉 | 「冶炼金属」✅ | 「冶炼金属」✅ |
| **配方下拉** | **空的** ❌ | `铁锭 x50 <= 铁矿 x100` ✅ |
| 燃料设置按钮 | ✅ | ✅ |
| 进度 / 材料取用范围 | ✅ | ✅ |

**证实了假设**：`window_furnace` 的控件依赖 **prefab 上的组件**，
`class_name` 改不了它 —— `furnace` 预制体自带 `FacilityFurnace`，
而 `trading_desk` 自带 `FacilityTradingDesk`。
诊断证据：105051 的窗口里 **`furnace` 字段是 null**（`facility` 有值但 `furnace` 没有）。

→ **工业 mod 的高炉必须用 `FacilityFurnace` 的原生骨架**（`furnace`，2×2），
燃料交互才可用。3×3 借骨架的方案做不出可交互的燃料界面。

## 修「配方为空」
根因：配方 UI 按 `facility_id` 从 `blueprint.json` 取行，
新建筑（105052）**不会自动继承**原生熔炉(105028) 的配方。

修法：新增 `clone_facility_blueprints()`，把原生熔炉的**全部配方**
克隆一份给我们的 id。要点：
  * **只新增**属于我们 id 的行，**不动** 105028 的行
    （改原版表 = 跨 mod 写同一张表，有冲突风险，也会改坏原生熔炉）
  * `formula_id` 保持 `product_id` 前缀、只换末尾序号，避开原生已用的 id
  * 同一 (product_id, 材料组合) 去重
  * `need_research=0`（开局可用）

实测克隆结果（105052 / 105051 各 8 条）：
```
铁锭×50   ← 铁矿×100   days=3
秘银锭×1  ← 秘银矿×40  days=5
精金锭×1  ← 精金矿×40  days=5
山铜锭×1  ← 山铜矿×40  days=5
黄金×1    ← 金矿×400   days=8
白银×10   ← 银矿×400   days=10
白银×10   ← 银币×1020  days=10
银币×990  ← 白银×10    days=10
```
镜像验证：plugins/1006/Defs/blueprint.json 现为 26 行（4 个 facility_id 都在）。

## 另外发现（重要）
`make_defs.py --deploy` 是**整体覆盖** `Defs/*.json`，
而游戏镜像到 `plugins/<槽位>/Defs/` 的副本**只在启动时刷新** ——
部署后**必须重启游戏**才会生效（否则跑的是旧数据）。
本次就踩到了：部署完没重启，窗口里配方还是空的。
