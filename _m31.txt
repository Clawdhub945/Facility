隔离测试工具：F11 热键切换 UI + cfg 真正热重载（BepInEx 默认不重读文件）

## 用户反馈（关键信息）
1. 「cfg 文件操作游戏内无任何变化」→ **cfg 不热重载**
2. 「点击 3*3 高炉后原版 UI 和自制 UI 一起打开了」

## 修法 1：cfg 真正热重载
**根因**：BepInEx 的 `ConfigEntry.Value` 是**内存值**，外部改动 cfg 文件**不会自动生效**，
必须显式 `ConfigFile.Reload()`。我之前的注释写"热生效"是错的。

新增 `Plugin.PollConfigReload()`：按 cfg 文件**修改时间**做轻量轮询
（每 `Update` 一次 `GetLastWriteTimeUtc`，变化才 `Reload()`），
在 `FacilityComponent.Update` 里调用。

## 修法 2：F11 热键切换我们的 UI（不依赖 cfg）
```
F11 → 隐藏/显示我们的面板
```
用途：**隔离测试** —— 隐藏后看游戏窗口能否正常关闭/点击/拖动。
* 不用 F9（已被历史诊断热键占用）
* 不用 F12（实测游戏收不到该键）

`UiKit.ToggleVisible()` 用 `_forceHidden` 标记，`SyncVisibility()` 会尊重它。

## 关于"原版 UI 和自制 UI 一起打开"
这是**预期行为**：3×3 高炉（105054）借的是 `window_gatherers_hut` 窗口，
所以游戏原生界面（覆盖率/库存格子/产量）**和**我们的面板会同时出现。
我们的面板是补上"冶炼信息"（配方/状态/燃料），不是替代原生界面。
若用户希望隐藏原版界面，可在 `BuildingSpec.BlastFurnace3.HideControls` 里加名单。

## 待用户验证（隔离测试）
1. 重启游戏（新 DLL 需要重启）
2. 打开 3×3 高炉
3. 按 **F11** 隐藏我们的面板
4. 试试点窗口的关闭按钮
   * **能关** → 确认是我们的 UI 影响输入 → 继续查（可能是 Overlay Canvas 影响了游戏的输入判定）
   * **仍不能关** → **与我们的 UI 无关** → 查其他方向（如叠加层 mod、游戏自身状态）
