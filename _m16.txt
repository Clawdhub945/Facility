通用 UI 模板：渲染可行性已验证；定位问题未解决（需人工标定）

## 用户反馈
「和之前没有如何变化」—— 模板建出来了但屏幕上看不到。

## ✅ 已验证可行的部分
1. **运行时构建 uGUI 完全可行**（`UiProbe` 五步全通过，游戏稳定）：
   新建物体 / SetParent / RectTransform / Image / TextMeshProUGUI 都成功
2. **模板骨架建得出来**：`UI 模板已构建：面板 260×150（建筑「高炉(3×3)」）`
3. **数据链路通**：状态签名、物品图标解析、状态行/进度行的取值逻辑都到位

## ❌ 未解决：**面板定位**
排查过程中确认的关键事实（都是硬约束）：

| 事实 | 证据 | 后果 |
|---|---|---|
| 窗口根的 `rect` 是 **550×0** | 诊断：`window_gatherers_hut size=550x0` | **任何 `anchorMin=0/anchorMax=1` 的拉伸写法都得到高度 0** |
| 游戏自己的子控件也是 `550×0` | 诊断：`title_area / content_area / tips_root` 全是 `size=550x0` | 不能用它们当"可视区"参照 |
| 拉伸的洋红遮罩只出现一条 0 高度残条 | 实测 | 拉伸方案**确认不可行** |
| **中心锚点 + 明确 sizeDelta 的红块能渲染** | 实测（截图里出现过红块） | **这是唯一可行的定位方式** |

试过并**失败**的定位方案：
* 以窗口根为参照的 `anchoredPosition` → 面板落在 y<0（可视区外）
* 复制锚点子控件的 anchorMin/Max → 同样 y<0
* 直接写 `RectTransform.position`（绝对屏幕坐标）→ y 仍是负值
* 用锚点尺寸推算面板尺寸 → 算出 260×56 这种畸形尺寸

当前状态：面板用「中心锚点 + 260×150 + cfg 偏移（默认 240,-170）」，
坐标 `x=2..262 y=-2..-152`（在 Canvas 内但屏幕上仍看不到）。

## 改进：把"标定"做成可交互的
* `UiProbe` 现在画的不再是全屏遮罩，而是**与模板面板完全同参数的红块**
  （同锚点、同 `sizeDelta`、同 cfg 偏移）→ 看到红块在哪，面板就会在哪
* 偏移量抽到 cfg：`[UI模板] 横偏移 / 纵偏移`（热生效，不用重编译）
* 新增诊断 `DumpChildren()`：列出窗口一级子控件的屏幕区，便于找参照物

## 结论
**渲染不是问题，定位是问题。** 需要人工看一眼红块位置才能一次标定成功 ——
自动化截图一直被「联机帝国」弹窗遮挡，效率极低。
