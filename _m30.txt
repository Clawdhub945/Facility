UI 交互隔离测试：加总开关 + 隐藏开关（用来确定"挡操作"到底是不是我们的 UI）

## 用户反馈（第二次）
「还是无法关闭，无法点击，无法移动」（附截图：3×3 高炉面板六行内容渲染完全正常）

## 我做的修复（上一轮，已验证生效）
* 移除 `GraphicRaycaster`
* 所有 `Image.raycastTarget = false`
* Canvas 加 `CanvasGroup { blocksRaycasts=false, interactable=false }`

## 新增：输入穿透自检（`InputPassthroughCheck.cs`）
进档自动跑（详细模式），把"谁在拦输入"的**确定性数据**打进日志。实测结果：
```
① EventSystem 数量 = 1
② 场景 GraphicRaycaster 数量 = 2          ← 都是游戏自己的
③ 我们的 Canvas: layer=5 order=20000 override=False active=True
③   GraphicRaycaster=无 ✔
③   CanvasGroup=blocksRaycasts=False interactable=False ✔
③   Graphic 总数=11，其中 raycastTarget=true 的 = 0 ✔
```
→ **从系统层面看，我们的 UI 不可能拦截输入**（无 Raycaster、无 raycastTarget、CanvasGroup 禁止拦截）。
但用户现象依然存在 → 需要**隔离测试**来定位真正原因，而不是继续猜。

## 新增：两个 cfg 开关（热生效，用于隔离）
```ini
[UI模板]
启用 = true     # 总开关：false 则完全不创建我们的 UI
显示 = true     # 临时隐藏面板（保留对象）
```
**测试方法**：在游戏里把「显示」改成 false（或「启用」改 false），
立刻看游戏窗口能否正常关闭/点击/拖动：
* **能** → 确认是我们的 UI 造成的 → 继续查（可能是 Overlay Canvas 影响了游戏的输入判定）
* **不能** → 说明**与我们的 UI 无关**，是游戏自身/其他 mod（例如 UnityExplorer 叠加层）的问题
