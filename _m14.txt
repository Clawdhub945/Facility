修两个 bug：3×3 高炉被当生产所 + 自研炉日志刷屏

## 用户反馈
「新建的 3×3高炉 功能和之前的生产所一样 UI还是乱的」

## 根因（我引入的）：自绘选择条的判据用错了对象
`FacilityWindowUi.Apply` 里决定"要不要画自绘选择条（额外产品下拉）"的条件是：
```csharp
if (spec.FillExtraProductDropdown) return;          // 只有「有原生下拉」的建筑才跳过
var coverage = FindText(window, "txt_forest_coverage_rate");
if (coverage == null) return;                        // ← 判据是「窗口里有没有这段文本」
var bar = EnsureSelector(window);                    // → 于是给 3×3 高炉也画了一条
```
`txt_forest_coverage_rate` 是**采集营地窗口**的固有文本，
而 3×3 高炉借的正是这个窗口 → 被画上「额外产品」下拉，
配合窗口原本的「附近森林覆盖率90%」，看起来就跟生产所一模一样。

**修法**：判据改成**建筑规格**：
```csharp
if (!spec.FillExtraProductDropdown) return;   // 只有声明要它的建筑才画
```
同时修正规格表里两座建筑的开关语义：
* `Producer`（综合生产所）：`FillExtraProductDropdown = true`
  —— 它**没有**原生下拉，用本 mod **自绘**的那条，所以必须为 true
* `SuperProducer`（超级生产所）：`false`
  —— 它用窗口**自带**的原生下拉 `dp_blueprint`（由 NativeDropdown 填候选）

⚠ 教训：**「要不要做某件事」必须看建筑规格，不能看窗口里有什么** ——
多座建筑可以共用同一个窗口预制体，用窗口内容当判据必然串味。

## 顺带修：详细日志刷屏
`Apply` 被窗口刷新方法**每帧**调用，而窗口里的三套诊断
（`DumpBoundFacility` / `DumpFurnaceRecipeDropdown` / `DumpAllDropdowns`）
原来每帧都打 → 日志被刷爆。改为**每个窗口只打一次**（`_diagDone` 按实例 ID 去重）。

## 实测：3×3 自研炉工作正常 ✔
```
冶炼炉候选：guid=27937056 stuff_id=105054 规格「高炉(3×3)」
高炉 guid=27937056 未开工：缺少原料 603001（需要 2，现有 0）
本日无冶炼产出（候选炉子 1 座；原因见上方的「未开工」日志）
```
* 规格分派正确：`window_gatherers_hut → 建筑「高炉(3×3)」`
* **bag 读取成功**（能准确报出「现有 0」）→ 反射取字典那条路是通的
* 只差玩家往仓库里放**铁锭**（603001）

## 2×2 高炉「找不到燃料」的原因（已查明）
反编译实证：
```c
FacilityBonfire/Furnace.AddStuffToBag(stuff_id, count):
    remain_fuel += count;      // 燃料进**建筑自己的仓库** → 转成"剩余燃料"
```
即**燃料必须进建筑仓库**，放附近地面不算（用户实测"附近已经放了燃料"仍不行，就是这个原因）。
另外 `FacilityFireController.ConsumeFuelOnNewDay` 每天扣 `fuel_cost_per_day`，扣到 0 就停火。

→ 2×2 版要跑起来，得让搬运工把煤搬进建筑（或手动放进去）。
3×3 自研版**不受这套机制影响**（自己从仓库读料扣除）。

## 新增诊断日志
`SmelterConsumer.ProcessAll` 现在会打：
* 每座候选炉子（guid / stuff_id / 规格名）
* 未开工的**具体原因**（缺什么料、需要多少、现有多少）
* 一天结束时的汇总
