彻底修掉 WindowGatherersHut.ShowWindowTip 空引用（护栏判据换成窗口名）

## 现象
```
System.NullReferenceException at WindowGatherersHut.ShowWindowTip()
```
连续报错（一次启动内 214 次 NullReference、106 次定位到该方法），
且**加了护栏也没用**。

## 排查（三步定位到判据用错）
反编译实证它为什么崩：
```c
gatherers_hut = this->fields.gatherers_hut;
if ( !gatherers_hut ) sub_1803AB740();        // ← 空引用崩在这
if ((hill_forest_coverage_rate + land_forest_coverage_rate) < 0.5) …
// 它还需要调用基类 WindowWorkFacility.ShowWindowTip()
```
即窗口必须绑着 `FacilityGatherersHut`。

排查看到的关键事实：
1. 护栏**确实挂上了**（挂载日志列出 9 个方法，含 `WindowGatherersHut.ShowWindowTip`）
2. 但**"护栏检查"探针一次都没打印** → 说明判据当时返回了"放行"
3. 报错紧跟在**我们窗口的诊断日志**之后 → **是我们的窗口崩的**，不是原版的

→ **根因：判据「字段在不在」不可靠** ——
`ShowWindowTip` 被调用的**时机早于字段绑定完成**，
探针还没看到字段、方法内部就已经抛空引用了。

## 修法
`ShowWindowTip` 系的护栏判据改为「**窗口预制体名**是否属于本 mod 建筑」：
* 窗口名来自 `build.json` 的 `window_prefab`（`BuildingSpec.WindowPrefab`），
  **稳定、不依赖任何时序**
* 是本 mod 窗口 → 跳过（这些方法依赖未绑定的设施对象）
* 原版窗口 → 完全放行

## 实测
```
本次启动后：NullReference = 0    ShowWindowTip = 0    ✔
```

## 教训（写进代码注释）
**护栏的判据必须在"方法被调用的那一刻"就成立** ——
用运行时字段状态当时序判据，会在对象还没绑好时误判放行，
护栏形同虚设。窗口名/预制体名这类静态信息才是可靠判据。
