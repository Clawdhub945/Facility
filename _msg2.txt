严重修复：把游戏原版制造台的 UI 改坏了（归属判断 fail-safe + 禁止按物体名全局搜）

## 用户反馈（附截图对比）
「图1是正常的，图2是被你改乱改少的。你把游戏内原来的UI也搞乱了，
  比如这个材料取用范围，还有进度等」
图1（正常）：材料需求图标 6 +「进度 0%」+「材料取用范围 50」带数字
图2（被我改坏）：这些整块消失，只剩「材料取用范围」标题

## 两个根因（都已修）

### 根因 1：`IsOurWindow` 判不出来时"放行"
早期版本取不到 `stuff_id` 字段就 `return true`（当时的想法是「宁可多改，
也别让我们的窗口没下拉框」）—— 结果**游戏原版制造台的窗口也被我们的代码处理了**。
关键背景：我们的建筑(105050) 和原版制造台(105010) 用**同一个**
`window_prefab = window_blacksmith`（用户要求"用游戏内 UI"后换过去的），
两者组件类型相同，**只有 `stuff_id` / `facility_guid` 能区分**。

修法：`IsOurWindow` 改为 **fail-safe** ——
  1. `stuff_id` == 本 mod 设施 id → true
  2. `facility_guid` 命中本 mod 建筑 → true
  3. **都取不到 → false（不动它）**
并加了 guid 缓存（`CacheManagedGuids`），因为 `Apply` 在窗口开着时每帧都会跑，
不能每帧 `FindObjectsOfType` 扫场景；归属判断的日志也做了去重（原来会刷屏）。

### 根因 2：`NativeUi.FindRaw` 的"按物体名全局搜"兜底
`HideAll` 命中不到字段时会退化成「在整棵层级里按物体名找」——
而制造台窗口里也有 `res_grid` / `my_progress_make` /
`num_adjust_of_materials_access_range` 这些**同名物体**，于是被一起隐藏了。

修法：`byNameFallback` 默认改为 **false**（只走正规的 `[SerializeField]` 字段反射，
只会命中该窗口类型真正持有的控件）。需要诊断时才显式打开。

## 新增回归验证手段
`F10` 现在会**优先打开原版制造台(105010)**（若场景里有），再打开我们的建筑 ——
用来回归验证「制造台窗口不再被动」。配合归属判断日志：
`[FacilityUI] 归属判断: facility_guid=<guid> → 我们的 / 原版的（不动）`

## 实测
- 我们的窗口：`归属判断: facility_guid=27249342 → 我们的`（只打一次，不刷屏）
- 原生下拉正常：截图里显示「秘银矿 +10/日」，点击可切换
- 原版窗口：命中归属判断第 3 条 → 完全不处理
