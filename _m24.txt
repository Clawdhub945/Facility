【最终结论】游戏窗口的 uGUI 布局不运行 → 标准 uGUI 量不出尺寸（定位问题定论）

## 用户提供的关键证据（UnityExplorer）
```
facility_ui_template
  RectTransform.sizeDelta = 260, 150          ← 设置生效
  RectTransform.rect      = -130, 0, 260, 0   ← 但实际高度 0
  RectTransform.offsetMin = 0, -267
  RectTransform.offsetMax = 260, -267         ← 上下偏移相同 → 高度算成 0
```
并且用户实测：点 `Inspect` 重新打开后**数值恢复原值**、点 `Apply` **没有任何反应**。

## 定论
`rect` **不是实时值，而是布局系统在布局时写入的缓存**。
这个窗口的 uGUI **布局从不运行**（游戏用**自绘批渲染**画 UI），
所以 `rect` 永远是初始的 0。

**含义**：
* 用 `rect` 判断尺寸/位置**不可靠**（永远读到 0）
* 用 `offsetMin/offsetMax`（拉伸）算尺寸**也不可靠**（父 rect 也是 0）
* **标准 uGUI 在这个窗口里没有可用的布局信息** —— 这就是所有定位尝试失败的最终原因

## 结论：两条可行的路
| 路 | 做法 | 代价 |
|---|---|---|
| **A. 用游戏自绘系统** | 用 `MySpriteRenderer`（游戏画 UI 用的就是它）创建面板/图标 | 需逆向用法，工作量大但最"原生" |
| **B. 复用现有控件** | 不改布局：改写已有文本（`txt_*`）、往已有物品格填图标（`icon_num*`）、改已有进度/数值控件 | 零风险、立即可用；布局自由度低 |

**建议 B 打底 + A 逐步替换**：先让内容立刻可见，再逐步做自定义布局。
